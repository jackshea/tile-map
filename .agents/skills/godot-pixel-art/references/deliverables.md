# 实际资源交付规范

用户要求“制作资源”“生成 Tile”“能在 Godot 中使用”时采用以下默认交付；仅规划、仅提示词或明确仅要图片时不扩展交付范围。规划文档中也应为计划制作的每类资源写明最终交付文件。

## Tile：默认交付可用资源包

一个 Tile 资源包至少包含：

| 文件 | 必须包含的内容 | 完成标准 |
| --- | --- | --- |
| `terrain_<主题>_atlas.png` | 精确 32×32 切片组成的 PNG 图集；多个图集时清单明确各自用途 | 实测尺寸、布局、背景与接缝符合规格，无设计板标签或辅助网格 |
| `terrain_<主题>.tres` | 可加载的 `TileSet`；32×32 tile size；配置好引用图片的 atlas source、区域尺寸和实际切片 | 用户赋给 `TileMapLayer.tile_set` 后即可选块绘制，不需要重新手动切图 |
| `terrain_<主题>_demo.tscn` | 引用交付 `.tres` 的最小示例场景；最近邻显示；必要的视野/相机设置 | 用户打开并运行当前场景即可看到代表性布局；不修改项目主场景 |
| `atlas_layout.json` | 文件路径、单格尺寸、列行数、边距/间距、资源 ID 到 atlas 坐标映射；需要时附多格区域和地形连接映射 | 和实际 PNG、`.tres` 一致，可据此复查、切图和扩展 |
| `使用说明.md` | 目标 Godot 版本、放置目录、打开方式、可用绘制功能、验证结果及限制 | 简短可操作；注明已有或未配置的碰撞/导航、是否支持自动连接 |

`preview.png` 建议提供，便于不启动引擎也能预览；已有实际演示截图可复用。预览不替代 PNG 图集、TileSet 或场景。

### 自动拼接与大物件

- 要求自动拼接的地形：在 `.tres` 中实际配置 terrain set、terrain ID、匹配模式和所需 peering bits；测试代表性绘制与擦除。只在使用说明中描述配置步骤，不算完成自动拼接交付。
- 只需单块绘制的图集：配置好 atlas 即可，不凭空增加 terrain。明确它支持手动绘制。
- 固定多 Tile 物件：提供可用 Pattern 或适用的多格区域，并在示例中完整放置；需要独立排序/交互时采用场景方案。
- 自动连接演示应覆盖实际支持的中心、边、内外角、孤岛、窄通道或孔洞；多种地形需要展示支持的过渡，不宣称缺失的组合也可用。
- 碰撞、导航仅在本次玩法需要时配置；提供时必须检查形状和行为，未提供时明确写出。

### 默认目录示例

沿用已有资源结构；没有对应目录时可以使用：

```text
assets/tiles/<主题>/
  terrain_<主题>_atlas.png
  terrain_<主题>.tres
  terrain_<主题>_demo.tscn
  atlas_layout.json
  preview.png
  使用说明.md
```

模板路径在实际交付时必须替换为真实名称。新增自包含资源包优先让图片、TileSet 和演示引用同一份交付资源，避免各复制一份后配置漂移；扩展现有独立 TileSet 副本时保留项目原有组织并明确同步范围。

## 其他类型的默认交付

| 类型 | 图片与元数据 | 要求 Godot 可用时的接入产物 |
| --- | --- | --- |
| 独立道具/建筑 | 透明 PNG 或分层 PNG；尺寸、占地、脚底锚点、状态说明 | `.tscn` 引用图片，设置位置偏移/排序；交互范围与碰撞按需求配置 |
| 角色动画 | 规则 Sprite Sheet 或等尺寸序列帧；动作、方向、帧顺序、时序和锚点 | 配置好动画名、帧区域、播放速度和循环的 `SpriteFrames .tres`，以及使用 `AnimatedSprite2D` 的预览 `.tscn` |
| 序列帧 VFX | 透明帧图/图集；尺寸、时序、循环与混合需求 | 合适的动画资源与最小播放场景；使用特殊材质时一起交付 |
| UI 图标/按钮/面板 | PNG 或图集；目标显示尺寸、按钮状态、面板拉伸边界 | 图集需要对应 `AtlasTexture`；面板按需求提供 `StyleBoxTexture` 或 `NinePatchRect` 示例；需要时提供 `Theme`/控件预览 |
| 美术设计图 | 实际设计图及简短说明；色板和尺度依据 | 标明“设计参考”，无需伪造可导入的生产配置 |

具体节点和资源按项目版本及既有流程选择；已有合格配置可复用。只要求静态角色时不补造动画，只要求图标时不构建完整 UI。若完整交付还依赖脚本、材质或其他图片，一并列入清单，不能留下仅在制作环境可用的隐藏依赖。

## 可移交与可复现

- 资源引用使用项目内有效路径，不能引用用户电脑的绝对路径、临时附件目录或制作缓存。
- 在当前项目交付时提供真实路径和打开步骤；要求迁移时给出完整资源目录及预期 `res://` 路径，在隔离的目标项目验证引用。只复制 `.tres` 而漏掉图片不算完整移交。
- `.godot` 缓存不作为交付依赖；导入应能重新生成需要的缓存。不擅自搬迁已有资源来凑目录示例。
- 使用项目已有构建工具时说明命令与会覆盖的文件；仅在确有复现价值时附生成/打包脚本，不为一次静态资源增加运行时依赖。
- 最终列出每项文件的用途、验证情况和剩余限制。已通过图片检查但尚未引擎导入的文件标为“静态检查通过，Godot 导入未验证”，不能写成“已可用”。

## 交付验收

1. 核对文件确实存在、布局数据与图片尺寸一致，所有本地资源引用能解析。
2. 在目标版本 Godot 中导入并加载 `.tres`、打开演示场景，检查日志；没有引擎时保留产物并标明未验证。
3. 按资源功能测试：Tile 手动绘制或 terrain 自动连接、Pattern 放置、动画播放、锚点与排序；碰撞和导航按实际提供范围测试。
4. 目视核对运行画面。无头加载通过仅证明加载，不证明显示、拼接观感或交互效果正确。

详细画面标准见[资源规格](asset-spec.md)，当前项目命令及副作用见[项目接入](godot-project.md)。用户已授权完整资源制作时按上述步骤继续完成，无需在每种文件之间重复申请确认。
