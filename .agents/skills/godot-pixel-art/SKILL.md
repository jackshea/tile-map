# Godot 像素美术规划与生产

把玩法需求转成风格一致、可拼接、可扩展、可验证的美术交付。使用中文说明；生成提示词可使用英文，资源标识使用英文 snake_case。

## 选择本次交付

| 用户请求 | 执行范围 | 按需读取 |
| --- | --- | --- |
| 规划美术、资源需求文档、增加一批资源 | 风格约定、规格、资源清单、优先级、制作顺序；常规完整规划附相关提示词 | [资源规格](references/asset-spec.md) |
| 只要提示词 | 复用已有风格与规格，只输出所需类型的提示词 | [提示词](references/prompts.md) |
| 生成图片、制作实际资源 | 直接制作本次所需资源，按要求选择图片或 Godot 资源包；不先写完整规划 | [交付规范](references/deliverables.md)；仅在需要时读资源规格、提示词和项目接入 |
| 检查资源、Godot 接入 | 核对实际文件与运行效果，报告通过项、缺陷和未验证项 | [项目接入](references/godot-project.md)、相关资源规格 |

用户只要规划或提示词时不启动图像生成；只改一项时输出差量。制作时先判断视觉是否需要生成模型：纯色、有限色板噪声、规则图案、掩码和连接切片可优先复用现有素材或用确定性绘制工具在原生像素尺寸制作；造型、笔触和复杂材质需要美术判断时使用可用的图像生成工具，并遵守其工具及 imagegen 技能说明。生成模型的输出只作源素材，实测尺寸和接缝后再作为生产资源；工具不可用时不要声称已生成。

**速度与范围**：直接制作请求只做用户点名的种类与必要切片，不自动扩成资源规划或完整场景。“简单做”“不需要过度”等表述优先走最小交付：一张可切片图集及必要的坐标说明；只有要求 Godot 可直接绘制、自动连接或演示时才增加相应资源。复用项目已有色板、脚本和合格样板，避免为同一套简单材质逐张生成大图后再缩成 32×32。

## 不变的规格边界

- 基础地图 Tile 为 **32×32 px**。大型网格模块可为其整数倍；角色、UI、VFX、独立 Sprite 不强制为整数倍。
- **画布尺寸、视觉覆盖、逻辑占地、碰撞范围分别定义**。64×96 图片覆盖 2×3 个图像格，不代表占地或碰撞也是 2×3。
- 角色不受 Tile 尺寸限制；统一角色与门、桌、树的比例，动画所有帧共用脚底锚点。
- 同一套资源共享视角、逻辑像素密度、色板、描边和光源。固定方向光照下，不随意镜像非对称或带阴影的资源来省朝向。
- 无缝地形、固定组合 Pattern、独立 Sprite/场景分别规划。缺少边角素材时不能靠配置获得任意形状的自动连接。
- 设计图用于说明效果；生产候选必须满足切片布局与文件规格。提示词写了“可直接导入”不构成验收证据。

## 工作流程

### 1. 读取最少的项目上下文

优先沿用本轮明确要求，其次只读本次需要的参考图、美术规范和目标资源。修改已有资源、运行仓库脚本或接入 Godot 前读[项目接入](references/godot-project.md)并检查工作区；仅新建独立图片时，检查目标目录与工作区即可。`project.godot` 和目标 TileSet/场景按接入需要读取。

识别玩法、视角、主题、目标平台、核心交互、程序生成/地形连接需求、室内外范围、角色动作及本次交付类型。不要把全部输入项变成问卷；仅就会改变交付结果且无法从项目判断的问题提问，继续处理独立部分。

无既有约定时，明确标注“默认采用”：俯视 2D、中低细节密度、左上光、有限色板、角色候选画布 48×64。题材、地形种类及角色动作按玩法补全，不无条件加入木屋、NPC、战斗、季节或 UI。Godot 版本从项目读取；缺失则注明待确认。

### 2. 固定可复用的风格约定

简短记录：视角与尺度、像素细节密度、调色板及用途、光源、描边、材质表达、视觉层级。背景保持低干扰，交互物用轮廓或对比度可辨认；角色在目标显示尺寸下清晰。输出真实色值或引用已验证的色板文件，避免只有“温馨、精美”等形容词。

延续已有资源时先看代表图，写清复用哪些特征及本次变化。涉及多个类别和尺度关系时用小样组合检查地面、交互物和角色；只做单类瓦片时直接检查图集的原生尺寸、整数倍放大与拼接。已有合格样板时直接复用。

### 3. 规划任务：把玩法拆成资源与依赖

仅在用户要规划或资源清单时执行此步；直接制作单批资源时跳过。只纳入当前范围涉及的地形、建筑、家具、植被、道具、角色、怪物、VFX、UI。按[资源规格](references/asset-spec.md)输出清单与必要的地形、物件、动画补充表。

- **P0**：支撑本次可玩闭环的最小资源，不能把所有类别自动列为必做。
- **P1**：增加玩法范围或明显改善重复感的扩展。
- **P2**：氛围与次要装饰；未来 biome、季节等只列建议，不扩成当前工作。

复用已有合格资源；区分缺口、新增和变体。按依赖安排制作：风格样板 → 地形与必要连接 → 关键模块/角色比例 → 其余内容。角色与建筑尺寸耦合时提前验证，不机械套固定出图顺序。

### 4. 交付所需成果

完整规划包含：简要方向与默认值、32×32/拼接规则、P0/P1/P2 清单、相关角色与大物件规格、Godot 组织方案、制作顺序与数量估算、所需提示词、验收标准。无需为无关类别输出空章节。

**实际资源交付按[交付规范](references/deliverables.md)执行。** 简单 Tile 制作先交付精确切片的 PNG 图集；用户要求直接在 Godot 绘制时增加 TileSet `.tres`，要求演示时增加 `.tscn`，需要自动连接时配置对应 terrain 规则。独立图集文件不等于完整的 Godot 接入。角色、道具、UI/VFX 按本次用途提供必要配置。用户明确只要 PNG 或设计图时遵守其范围。

设计图与生产资源分开命名、标明用途。仅在使用生成模型或用户要提示词时展开[提示词模板](references/prompts.md)，共享风格块只定义一次。提示词不需要时省略。

用户要求落盘文档时沿用项目文档位置；尚无约定则用 `docs/art/<主题>.md`。资源沿用项目目录；没有约定才按 `assets/tiles`、`props`、`buildings`、`characters`、`fx`、`ui` 创建实际需要的子目录。

### 5. 按交付级别验收

规划阶段检查范围、数量、规格是否自洽；出图阶段检查实际像素尺寸、透明通道、画面和接缝；接入阶段检查 TileSet 引用、地形规则、排序和实际显示。检查细节见[资源规格](references/asset-spec.md)与[项目接入](references/godot-project.md)。

报告应区分“规划完成 / 图片已生成 / 静态验证通过 / Godot 导入通过 / 运行效果已验收”。未实际执行的检查标为未验证，并给出具体缺口。失败时针对问题修正，已经通过的无关资源不重新生成。

- `使用 $godot-pixel-art，沿用现有色板生成一棵 64×96 的树，逻辑占地 1×1，透明背景。`
- `使用 $godot-pixel-art，制作一套草地与泥土地形，交付可在 Godot 中自动拼接的图集、TileSet 和演示场景。`
- `使用 $godot-pixel-art，检查这套地形的拼接完整性并列出缺少的切片。`
